# Calxus 使用说明

Calxus 是一台由上行 USB 供电、用硬件选择接口的计算器连接转换器。计算器传输继续使用原有软件；Calxus 无需安装自己的上位机应用。首次使用先完成[装配与首板检查](assembly-and-bringup.zh-CN.md)。本版为工程样机资料，软件路径已经查证，实物功能按[验证记录](validation-record.zh-CN.md)逐项登记。

## 选档与连接

上行 USB-C 接电脑，使用支持数据传输的 A-C 或 C-C 线。先退出传输软件、拔下上行线，再按丝印选择 USB 主档和串口支路；接好目标后重新接上行。主选择器为四档滑动开关，按壳体 NATIVE / USB-A / SILVER / UART 标记选择；`S1 S0` 是对应内部选择码，不是另加的 DIP 开关。

| 主档 `S1 S0` | 连接到电脑的 USB 功能 | 接口用途 | 电脑端软件 |
|---|---|---|---|
| `00` | 原生 USB 直通 | 固定 Mini-B 尾线接计算器原生 USB 口 | 对应型号的原厂软件或支持该型号的现有工具 |
| `01` | USB-A 直通 | USB-A 母座接外设或该计算器的原装 USB 线 | 由上行主机及外设决定 |
| `10` | TUSB3410 SilverLink B | 标记 `TI` 的 2.5 mm 尾线接 TI 双线 Link 口 | TI Connect 经典版、TILP 或 WebTILP，按具体型号选择 |
| `11` | CH343P USB 串口 | 另选 `CASIO` 固定尾线或 `AUX` 专用转接尾线 | FA-124 的 COM 模式、对应 HP 串口工具、串口终端 |

四档共用一条上行 USB 数据通道，**一次只启用一档**。`00` 与 `01` 不同时工作；`10` 与 `11` 也不同时枚举。不要因其他尾线插头外形相同而混用 TI 与 CASIO 线。TI 双线 Link 协议与 CASIO UART 不是同一种接口。

## TI 双线 Link

1. 主档设 `10`，连接 `TI` 2.5 mm 尾线与计算器 Link 口。
2. 接上行 USB。已正确写入 EEPROM 的转换器应显示 SilverLink 设备，硬件 ID 为 `VID_0451&PID_E001`。若为 `0451:3410`，它处于 ROM 引导阶段，先检查恢复跳帽和 EEPROM。
3. 使用经典 TI Connect 时安装其对应驱动；软件选择该型号支持的 USB Graph Link / SilverLink。不要把 TI Connect CE 当成所有旧式 Link 机型的统一替代品。
4. 使用 [WebTILP](https://web.tilp.info) 时，在支持 WebUSB 的浏览器里授权 SilverLink。Windows 可能需要用 Zadig 将 **SilverLink 这一个设备**绑定为 WinUSB。完成后先读目录，再做小文件传输。

TI Connect 与 WebTILP 在 Windows 上通常不能同时依赖同一个驱动绑定。换到 WinUSB 后原厂软件可能找不到该设备；返回原厂软件时恢复其驱动。关闭其他占用设备的程序和浏览器页面，再重新连接。驱动操作只针对选中的 SilverLink，不能改 CH343 串口或电脑 USB 控制器。

## 原生 USB

主档 `00` 的 Mini-B 尾线是一条经 USB 数据开关选择的原生设备连接。它不把 USB 变成 TI 双线或串口。对使用不同 USB 接口的计算器，主档设 `01`，从 USB-A 母座连接其原装数据线。

TI-Nspire 的文件传输走原生 USB；AUX 串口日志不替代这一通道。CASIO fx-9860G 系列使用 FA-124 时应选原生 USB 路径和 FA-124 的 USB 通信项。CH343P 出现 COM 口，并不表示所有原生 USB 计算器都能改走串口传输。

若原厂软件找不到设备，先检查主档、数据线及原厂驱动，再用原装线直接连电脑做对照。记录计算器型号、操作系统、软件版本和实际错误信息。

## CASIO 串口

仅用于 FA-124 或其他现有软件明确支持串行连接的机型。主档设 `11`，串口选择器设 `CASIO`，连接 CASIO 2.5 mm 尾线。CH343P 使用 WCH 官方串口驱动；设备管理器应出现 COM 端口。

FA-124 中选正确 Model Type，再在 Link → Communications 选择该 COM 口。某些旧软件只列出 COM1 至 COM9，可在 Windows 端口高级设置中给 CH343 分配一个未使用的低编号。计算器进入 LINK 的发送或接收状态，与电脑端操作配对。

已查证的 FA-124 COM 使用场景包括 ALGEBRA FX、CFX-9850G / fx-7400G 系列，以及手册指定的 fx-7400GII 场景；本版 Calxus 的电气与实际传输仍需按机型验收。不要把这里的 COM 路径宣传成 SB-88 的 USB 身份仿真。

## AUX：HP 与 TI-Nspire 日志

主档 `11`，串口选择器设 `AUX`，使用该机型专用、已校验针序的转接尾线。AUX 是 **3.3 V 逻辑域、非反相、空闲高电平 UART**，不是正负电压 RS-232。开漏 TX 经防反灌二极管上拉，实际高电平约 3.0–3.2 V，须与目标计算器输入要求及实测波形一并核对。板端四针定义如下：

| AUX 针号 | 定义 | 连接方向 |
|---:|---|---|
| 1 | GND | 与计算器信号地相连 |
| 2 | `AUX_RX` | 计算器 TX → Calxus 接收 |
| 3 | `AUX_TX` | Calxus 发送 → 计算器 RX |
| 4 | NC | 不接；不是电池或供电输出 |

HP 50g 的串口有专用连接器和接口行为，不能把普通 PC RS-232 电平接到 AUX。发送缓冲采用开漏释放高电平，减轻计算器关闭串口时的争用；仍需验证实际尾线、上升沿、关机及唤醒行为。HP 39gs 与其他型号须分别核对针序、电平和软件协议，不以外形相似推定通用。HP 48 系列的传统 RS-232 线不能直接当作 HP 50g 的 TTL 尾线。

TI-Nspire 日志使用已核对为 3.3 V 的目标引脚，终端通常设置 **115200、8 数据位、无校验、1 停止位、无流控**。首次只接 GND 和计算器 TX 到 AUX_RX，先接收开机日志；确认目标电平和版本后才接 AUX_TX。AUX 不给计算器供电，也不承诺所有 Nspire 底座或硬件版本针序相同。

## 供电与 USB Host 场景

正常供电来自上行 USB-C 的 VBUS。AUX、TI 和 CASIO 信号尾线不向计算器电池接口供电。下行 USB 电源属于上行主机的同一电流预算，不能把每个物理插口各按 500 mA 累加；外设和计算器的充电需求必须计入实测总电流。

若计算器本身支持 USB Host/OTG，可使用正确接出其 Host 角色和 VBUS 的 Mini-A 主机线接入 Calxus 上行，再选择所需功能。是否可用取决于该计算器能否供电、是否有对应 USB 类驱动和软件。Calxus 不给原本只有 USB Device 的计算器新增 Host 能力，也不以并接两端电源来解决供电。

## 故障定位

| 现象 | 优先检查 |
|---|---|
| 所有档位都不枚举 | 上行是否为数据线、USB-C 插接、VBUS 与选档；仅在串口两档测 3.3 V、TUSB 复位 |
| 原生档能用，TI 档显示 `0451:3410` | EEPROM SCL 恢复跳帽、镜像、EEPROM 电源与焊接 |
| TI Connect 可用但 WebTILP 不能打开 | SilverLink 驱动是否 WinUSB、浏览器 USB 授权、程序占用 |
| WebTILP 可用但 TI Connect 找不到 | 恢复对应原厂驱动并重新插拔 |
| UART 枚举但没有数据 | CASIO/AUX 支路、RX/TX 方向、地、波特率、计算器通信状态 |
| Nspire 有乱码 | 先核对 115200 8N1、电平和实测波形，再核对机型硬件版本 |
| 传输中断或复位 | 接头应力、线长、VBUS 压降、上行供电能力与信号波形 |

转换器固件的重新写入和恢复见[固件说明](../firmware/README.md)。开始恢复前断开计算器，确认目标是 Calxus 外部 EEPROM。
